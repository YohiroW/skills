# CRPG 对白写作

把需求写成玩家实际能参与的场景：有理由继续交谈，有空间表达自己，并能感知回应与后果。默认完成本轮要求的成稿。

## 接住需求

- 从对话、设定文件或已有稿件提取范围、人物、世界规则、玩家已知信息、语气、长度和指定格式。区分用户确定的事实与创作补充；沿用现有命名和事件。
- 信息较少时，采用少量合理假设并简短标明，然后交稿。只有无法通过合理假设解决的核心矛盾，才提出影响成稿的一个问题；不要把普通写作任务变成连续访谈。
- 按用户请求决定交付尺度：一句回应、短对白、完整分支、同伴场景或任务线。修改时围绕指定问题重写，保留无关设定和已有效的段落。
- 用户要求先追问、逐步构思时，转用配套的 [crpg-dialogue-coach](../crpg-dialogue-coach/SKILL.md)。

## 先确定场景，再写台词

内部确定这些内容；仅在对用户有用或用户要求时展示场景卡：

- 玩家进入前，人物正在做什么；眼前有什么需要回应的变化。
- NPC 当前想得到什么，为什么愿意与玩家交涉，有什么筹码、顾虑或盲点。
- 玩家身份、已知信息、先前行为，以及各人物此时实际知道的事情。
- 玩家可以用哪些不同手段参与；本次场景要改变什么，离开时留下什么线索、关系或问题。

## 写作取舍

1. **入口有事情发生。** 用正在进行的行动、具体异常、请求或关系变化引出交谈。轻松闲聊也可以由一个小需要开始；按用户语气决定张力大小。
2. **声音来自欲望和世界观。** 让人物如何请求、拒绝、误解和辩护反映其价值、恐惧与看待玩家的方式。留出矛盾与脆弱；口癖和修辞服务人物意图。
3. **信息回应好奇与行动。** 把必要行动信息讲清楚；背景披露沿着当前疑问展开。可选深问增加理解，必经路线仍应足以让玩家作决定。
4. **选项提供扮演空间。** 区分不同目的、手段或态度，让玩家看懂自己准备做什么。行动、沉默、退让、打趣和离开也可以成为选项。旁白侧重可感知线索；玩家情绪和立场由用户指定或交给玩家选择。
5. **重要选择有取舍。** 让相关人物的利益、关系、风险或信念发生冲突。呈现玩家能够察觉的风险；可以让结果出乎意料，同时保持选项意图清楚。失败可以产生代价、新局面或另一条进路，具体服从题材与任务要求。
6. **回应承认当前玩家。** 在与场景有关的位置响应身份、已知秘密、过去行动和关系。为需要后续兑现的选择记下具体事实，例如“答应守密”或“对方知道门禁卡被拿走”。NPC 的知识与记忆保持一致。
7. **人物各有计划。** 同伴可以请求接手、提出异议或带来自己的目标。把任务与同伴线的交会写成具体关系协商；在局部困境里逐步呈现世界主题。
8. **分支有回应，也有节奏。** 不同选项先得到合适反馈，再按需求回汇或分开；保留值得回访的差异。把重要转折留给值得投入的选择。让紧张、安静、幽默和伤痛按场景功能变化。

这些设计判断按场景的功能与规模取舍。以用户提供的世界、人物和事件为依据，忠于其体裁、调性和预算，创作符合当前设定的内容。

## 交付成稿

- 使用用户指定的格式；没有格式要求时，给出易读的旁白、人物发言与玩家选项。正文采用宿主支持的可复制写作块，创作说明放在正文外。
- 分支需要表达连接时使用稳定、唯一的节点编号，标清选项后继、回汇与出口。仅在接入需要时补充前置条件、状态变化和延后反馈；用易懂标注，技术细节与玩家看见的正文分开。
- 给关键表演写简短情境备注：说话者此刻想达到什么、在掩饰什么、怎样对待玩家。明确标为编剧或表演备注，单独列出或放在与玩家正文分开的区域；私密意图按设定中的叙述视角呈现。用户只要纯文本时尊重其格式。
- 用少量说明交代重要创作假设或改写取舍；避免用理论讲解代替成稿。概念剧情或任务概要按其尺度交付，无需强制展开成所有节点。

## 交稿前核对

- 分别沿每条实际路线阅读：只看这条路线的玩家能理解眼前问题，选项后的回应承认其行为，后继与出口可接上。
- 引用的节点存在；循环有离开方式；世界规则、时序、NPC 知情范围和状态变化相容。
- 即使遮住人物名，主要人物的目标和表达方式仍有区别；重复铺垫、说明与回汇不妨碍当前路线的节奏。
- 没有把用户未确定的设定当成既定事实，也没有替玩家加入未获授权的决定性动机。

完成条件是所请求的文本或结构已可阅读、分支可追踪，重要假设已明示。对白树的完整性检查不能代替真实试玩；用户请求评估可玩效果时，再观察玩家实际路线并据反馈修改。
